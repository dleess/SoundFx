# RECOVERY

## 기본 원칙

검증이 실패하면 곧바로 광범위한 수정에 들어가지 않는다. 진단부터 한다.

## 실패 루프

1. 실패 출력을 끝까지 읽는다.
2. 실패 유형을 분류한다: 구현 버그 / Gradle·SDK 환경 / 에뮬레이터 문제 / Android API 제약 / 권한 문제 / scope 충돌.
3. PRD(plan.md), PLAN.md, VALIDATION.md와 비교한다.
4. 가장 작은 가역 수정 1회를 한다.
5. 가장 작은 관련 검증부터 재실행한다.
6. PROGRESS.md를 업데이트한다.

## 재시도 한계

같은 검증이 서로 다른 3회 시도(3 attempts) 후에도 실패하면:

골이 진단·검토 모드로 전환되고 자체 수정을 멈춘다. Claude Code는 `/goal pause`를 지원하지 않으므로 사람의 결정을 기다린다. 필요하면 `/goal clear` 후 재설정한다.

보고: 실패 명령/기준, 시도한 3가지 수정, 각 실패 이유, 다음 안전 옵션, 사용자 결정 필요 여부.

## scope 잠금

다음은 금지한다:
- Play 스토어 배포·서명 설정 (배포는 lee.donghan@gmail.com 계정 — 차기 골)
- extension/, safari/ 수정 (1·2단계 산출물 보호)
- PLAN.md에 명시되지 않은 아키텍처 변경
- 검증을 통과시키기 위해 테스트를 삭제·skip
- 이해 없이 에러를 침묵 처리
- RECORD_AUDIO 등 과잉 권한 요구 (필요 최소 권한만 — MODIFY_AUDIO_SETTINGS, FOREGROUND_SERVICE 계열)
- 검증 명령 자체를 다른 명령으로 교체 (환경 버그 확인 시 오케스트레이터 승인 하에만)

## 방향 재확인 규칙

접근법을 바꾸기 전에: 골 문장 → PRD의 "만들지 않는 것" → PLAN.md 현재 마일스톤 순으로 다시 읽고, 다음 수정이 현재 마일스톤에 직접 기여하는지 확인한다.

## 되돌리기 규칙

자기 자신의 마지막 실패 변경만 되돌린다 (검증 악화 / 무관 변경 혼입 / PRD·PLAN 충돌 시). 사용자가 수동으로 만든 변경은 명시적 지시 없이 절대 되돌리지 않는다.
